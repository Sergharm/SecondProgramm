# Снимки первого чекпоинта LinuxSandbox

Семь PNG в `docs/screenshots/` сняты с реально запущенного LinuxSandbox в QTerminal. Для получения использовался локальный виртуальный экран Xvfb. Обрезка оставила области интерфейса, относящиеся к рисункам. TCP- и UDP-примеры исполнились внутри Bubblewrap от обычного пользователя в отдельном сетевом пространстве имён с loopback. На рисунке 8 используется схема, построенная по исходному коду. Внешняя сеть образцам не предоставлялась.

## Повторная съёмка

Из `CourseWork` под обычным пользователем соберите приложение и два примера вместе.

```sh
cmake -S . -B build
cmake --build build
./build/LinuxSandbox
```

Для сборки с `-DCMAKE_BUILD_TYPE=Release` используйте `./build/Release/LinuxSandbox` и аналоги `./build/Release/test_tcp`, `./build/Release/test_udp`. Выбирайте тест из той же сборки. Если при подготовке среды Bubblewrap не удаётся настроить loopback, остановите динамическую часть. В кадр включайте только указанный участок терминала. Используйте крупный шрифт и проверяйте снимок перед включением в отчёт.

| Рисунок | Команда и действия | Контрольный файл | Ожидаемая область кадра | Имя в `docs/screenshots/` |
| --- | --- | --- | --- | --- |
| 1. Главное меню | `./build/LinuxSandbox`. Дождаться приглашения. | Без выбора. | Название, версия, команды 1–6 и 0, поля текущего файла и ввода. | `01_menu.png` |
| 2. Выбор файла | В той же программе команда 1, ввести `./build/test_tcp`. | `test_tcp`. | Приглашение ввести путь, введённое значение и «Файл выбран». | `02_select.png` |
| 3. Свойства файла | После выбора TCP выполнить команду 2. | `test_tcp`. | Путь, `ELF`, размер и доступ на исполнение. | `03_info.png` |
| 4. Изолированный анализ | После выбора TCP выполнить команду 3. | `test_tcp`. | Номер команды и подтверждение завершения анализа с числом событий. | `04_analysis.png` |
| 5. Сетевые события TCP | После успешного анализа TCP выполнить команду 4. | `test_tcp`. | Строки с успешным `connect`, `accept`, обменом и `ECONNREFUSED`. | `05_tcp.png` |

Захватывайте фактический вывод. Порты, PID, время и имя отчёта могут изменяться. Снимки предназначены для сдачи вместе с отчётом. Перед передачей проверьте видимые пути и отсутствие сведений из домашнего каталога, почты или VPN.

Кафедральное ТЗ в предоставленных материалах предусматривает проверку исходного кода, в том числе многофайловой организации. Отдельное обязательное требование к скриншотам редактора в нём не найдено. Если преподаватель их запросит, откройте в VS Code дерево `src/`, `include/` и `tests/`, затем участки `src/IsolationManager.cpp` вокруг `command()` и `src/NetworkMonitor.cpp` вокруг `parse()`. Снимайте только Explorer и редактор. Сохраните под именами `source_structure.png`, `source_isolation.png` и `source_monitor.png`. Эти дополнительные файлы передаются отдельно от четырёхстраничного отчёта образца.

После добавления или замены снимков пересоберите отчёт.

```sh
python3 scripts/generate_reports.py --only checkpoint
```

Проверьте число страниц, подписи и читаемость TCP/UDP. Генератор сообщает об отсутствующих кадрах и оставляет подписанную позицию на соответствующей странице. При повторном запуске предыдущие версии документов копируются в `build-docs/backups/`.
